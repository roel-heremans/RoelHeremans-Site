# RoelHeremans-Site

Static, English-only site for roel-heremans.com (Roel Heremans, freelance data scientist: AI-accelerated, human-verified analytics), generated with Python + Jinja2. Built the same way as the NinaSuza, kombucha and sattva-reset sites. Every change is an edit to this repo plus a push.

Design and decisions: `docs/superpowers/specs/2026-10-31-roel-heremans-site-design.md`.

## Setup
    python3 -m venv .venv && . .venv/bin/activate
    pip install -r requirements.txt

## Build, test, preview
    ./build-output.sh                                  # writes output/
    pytest -q                                          # must be all green before a push
    python -m http.server -d output 8000               # http://localhost:8000/

## Page structure
Five main pages, each at `/<slug>/`:

| Page | URL | Template |
|---|---|---|
| Home | `/` | `home.html.j2` |
| Approach | `/approach/` | `approach.html.j2` |
| Work | `/work/` | `work.html.j2` |
| About | `/about/` | `about.html.j2` |
| Contact | `/contact/` | `contact.html.j2` |

Each earlier project also has a case-study page at `/work/<id>/` (SpryFox, Bef4U, Electrolux, Uptime, Your Political Monitor, fbeta, Intero – The Sniffers), all rendered by the one template `case-study.html.j2`. The projects are one list, `PROJECTS` at the top of `src/content.py`: it drives both the cards on Work and the case pages (added to `CONTENT["pages"]` at the bottom of the file, so they get the sitemap, titles and relative links like any page). To add a project, add an entry there. Facts come only from `docs/superpowers/specs/2026-10-31-case-study-pages.md`; copy numbers exactly.

Old Framer URLs still work through small redirect pages (`CONTENT["redirects"]`): `/project/bef4U`, `/project/Electrolux`, `/project/uptime`, `/project/PoliticalMonitor`, `/project/fbeta` and `/project/sniffers` go to the matching case-study page (the card anchors on Work stay too); `/de/` goes to Home (the German version was dropped). The CV is copied from `original/roel-heremans-cv.pdf` to `/cv/roel-heremans-cv.pdf`.

Shared parts (header, footer, closing call to action, checklist) are in `src/templates/partials/`; styles in `assets/css/styles.css`; the only script of our own is `assets/js/site.js` (phone menu, copy-email button, fade-in).

## Changing content
All texts, links and the email address live in `src/content.py`; templates are in `src/templates/`.

- Pages are listed in `CONTENT["pages"]` (id, template, slug, title, nav label, `in_nav`).
- The email shown everywhere is one value, `CONTENT["links"]["email"]`.
- Copy that appears on more than one page has one key: the closing call to action is `CONTENT["cta"]` (also the Contact lead), and the method lead is `CONTENT["approach"]["lead"]` (also on Home).
- Keep Roel's voice: first person, plain, concrete. No em-dashes.
- No Bitcoin address is published anywhere (a test checks the built HTML): each invoice comes with its own address.

After a change: `./build-output.sh && pytest -q`.

## Images
`assets/img/` is generated by `tools/prepare_images.py` (ImageMagick) from the photos in `original/images/`:

    python tools/prepare_images.py                  # everything
    python tools/prepare_images.py og.jpg           # just one file

It writes the hero, square and family portraits, `og.jpg` (1200x630) and `favicon.png`. The `<img>` sizes in `CONTENT["images"]` must match the files (a test checks this), and a test fails if an image in `assets/img/` is not used by any page. ImageMagick cannot read woff2, so `og.jpg` and `favicon.png` use the system fonts EB Garamond and Liberation Sans as stand-ins for Cormorant Garamond and Inter.

## Colours
Every colour is a CSS custom property in the one `:root` block at the top of `assets/css/styles.css` (ink blue `--brand`, `--brand-deep`, gold `--accent`, `--accent-text`, `--white`, `--bg`, …). A test fails if a hex/rgb/hsl colour appears anywhere else in the CSS, so changing the theme is a one-block edit. `--accent` (gold) is for buttons, rules and large words only; small gold text uses `--accent-text`, which a test checks for contrast. Fonts: Cormorant Garamond + Inter, self-hosted woff2 in `assets/fonts/` (SIL OFL).

## Visual review
    ./build-output.sh && python tools/screenshots.py
    python tools/screenshots.py https://roel-heremans.github.io/RoelHeremans-Site/

Screenshots every page (the five main pages and the case studies) at 1440px and 390px into `review/shots/`, writes a gallery `review/index.html` (`review/` is gitignored), checks every 390px page for horizontal scroll and the header at 960, 1100 and 1260px (the nav must stay on one row). Exits 1 and lists the problems if a check fails. Without a URL it serves `output/` itself (with the CORS header the web fonts need). Needs google-chrome and ImageMagick.

## Deploy (phase 1: GitHub Pages test site)
Pushing to `main` runs `.github/workflows/deploy.yml`: install, `pytest -q` (failing tests block the deploy), build, publish `output/` to
https://roel-heremans.github.io/RoelHeremans-Site/ (repo `roel-heremans/RoelHeremans-Site`; Settings, Pages, Source: GitHub Actions). While `CONTENT["preview"]` is True every page carries `<meta name="robots" content="noindex">`, which keeps the test site out of search engines.

## Deploy (phase 2: live site on STRATO)
The same workflow has a second job, `strato`, that builds with `SITE_ENV=production` (no `noindex`, canonical tags, robots.txt allows all and lists the sitemap, plus an `.htaccess` that redirects http to https and roel-heremans.com to https://www.roel-heremans.com/) and uploads `output/` over SFTP with `tools/deploy_strato.py`. It only runs when the repository variable `STRATO_DEPLOY` is `true`; the GitHub Pages test build stays `noindex`.

Settings, Secrets and variables, Actions:
- secrets `STRATO_HOST`, `STRATO_USER`, `STRATO_PASSWORD`, `STRATO_PORT` (22 unless STRATO says otherwise); same STRATO account as realhealthkombucha.com, so the same values;
- variables `STRATO_REMOTE_PATH` = `/roelheremans` and `STRATO_DEPLOY` = `true`.

The webspace also hosts realhealthkombucha.com and sattva-reset.com, so the script refuses the webspace root and any non-empty folder without its manifest `.roelheremans-deploy.json`; it uploads only changed files and deletes only files it put there itself, so it never touches the other sites' folders. The server's host key must match `tools/strato_known_hosts` (`ssh-keyscan -t ed25519,rsa <host>` if the host ever changes).

Going live:
1. Set the secrets and variables above. The first deploy creates the folder `/roelheremans` (no manual step in the STRATO panel needed for that).
2. In the STRATO panel, Domains: point roel-heremans.com and www.roel-heremans.com to the folder `/roelheremans`. This replaces the Framer A / CNAME records. Do NOT touch the MX records.
3. Keep Framer running until the new site is confirmed live (https, www redirect, a few pages), then cancel it.
